# 第四阶段待办清单

26 级 · 李昊泽 · 前端纯 HTML / CSS / JavaScript，后端 Node.js + Express + SQLite。

## 这是什么

用来记录我这一周第四阶段任务的待办清单：

- **列表页** `index.html`：新增、删除、按关键字筛选、只看未完成
- **详情页** `detail.html`：点任意一条进去看详细说明

数据不再写死在文件里，而是存在后端数据库 `server/data.db` 中。刷新页面数据不会丢。

## 功能

**前端**

- 新增待办（输入框 + 回车或点「新增」）
- 删除待办（每条右边的「删除」按钮，会二次确认）
- 按关键字实时筛选、只看未完成
- **三种状态都做了**：加载中 / 空数据 / 请求失败（带「重试」按钮）
- 手机 375px 宽度下正常显示，不出现横向滚动条

**后端**

- 5 个接口：查列表、按编号查一条、新增、删除、修改
- 数据存在 SQLite 文件里，服务重启后数据还在
- 参数校验：缺字段、类型不对返回 400 并说明原因，服务不会崩
- 全局错误处理：任何异常都返回 JSON，不会把 HTML 报错栈甩给前端
- 已开启跨域（CORS），浏览器里的网页可以直接调用

## 怎么在本地跑起来

**必须开两个终端，顺序不能反。**

### 终端 A：先启动后端

```powershell
cd D:\webone\server
npm install      # 只有第一次需要
npm start
```

看到「接口服务已启动 / http://localhost:4000」就对了。**这个窗口一直开着别关。**

### 终端 B：再启动前端

```powershell
cd D:\webone
npx serve .
```

它会给你一个地址，通常是 http://localhost:3000 ，用浏览器打开即可。

> 也可以用 VS Code 的 Live Server 插件打开 `index.html`，效果一样。

### 为什么不能直接双击 index.html

任务 1 时代可以，现在不行了。浏览器有一条安全规则：`file://` 协议下不允许网页去请求别的地址。双击打开时页面会显示「加载失败」，这不是代码坏了，是浏览器不让。所以必须用上面的小服务器打开。

## 目录结构

| 路径 | 作用 |
| --- | --- |
| `index.html` | 列表页 |
| `detail.html` | 详情页，靠网址里的 `?id=` 决定看哪一条 |
| `style.css` | 样式，含 375px 手机适配 |
| `config.js` | **配置**：只放后端地址，部署后改这里 |
| `app.js` | 前端逻辑：fetch 取数据、三态切换、新增、删除 |
| `server/index.js` | 后端：路由、CORS、参数校验、错误处理 |
| `server/db.js` | 后端：建表、首次运行写入初始数据 |
| `server/API.md` | 接口文档表 |
| `server/data.db` | SQLite 数据库文件（不进 git，会自动生成） |
| `.gitignore` | 不上传名单 |
| `.nojekyll` | GitHub Pages 用 |

## 换后端地址改哪里

只改 `config.js` 里这一行，别的代码不用动：

```js
const CONFIG = {
  API_BASE: "http://localhost:4000/api"
};
```

## 怎么自己触发三种状态（做截图用）

| 想看什么 | 怎么弄 |
| --- | --- |
| 加载中 | 把浏览器开发者工具 Network 调成 Slow 3G，再刷新 |
| 空数据 | 把所有待办都删掉，或在筛选框里输入一个不存在的词 |
| 请求失败 | 把后端那个终端 Ctrl+C 停掉，然后点页面上的「重试」 |
